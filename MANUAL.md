# MANUAL - things only the human can do

1. Set `SETTINGS_ENCRYPTION_KEY` in production `.env` (generate with `openssl rand -base64 32` - already generated and in `.env.local` on this machine for local dev). Required before any Razorpay secret can be saved; without it, saving a Key Secret/Webhook Secret throws a clear error rather than silently storing plaintext.
2. In Admin > Settings > Payments, paste test-mode Razorpay Key ID + Key Secret, flip the "Enable" toggle (this is the `provider_razorpay` feature flag), then set the webhook URL (`<your domain>/api/webhooks/razorpay`) in the Razorpay dashboard using the same webhook secret entered in that settings page. Use "Test connection" to confirm the keys work before relying on it.
3. Local dev seed (`pnpm db:seed`) creates no orders/entitlements/quotes/leads/queries/chat conversations, so those DETAIL screens and the full checkout flow couldn't be fully exercised by the automated audit. Please manually click through: register as a new customer, buy a product (try both manual UPI and, once configured, Razorpay test mode), submit a payment reference, then in admin confirm the payment and check /orders/[id], /account/orders/[id], /account/purchases. Report anything broken.
4. /finance/*, /content/*, /settings/*, /audit, /admin-users were NOT independently re-audited this round (the audit agent's dev server got corrupted by a concurrent `pnpm build` run - fixed by restarting, but not worth re-running the full audit for routes that cluster-9 commits already covered). Spot-check these if you have time, especially /settings/general (seller address/email/phone are still placeholder per A-010 until you enter real business info - that's expected, not a bug).
